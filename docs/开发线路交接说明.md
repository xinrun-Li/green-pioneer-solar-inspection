## 必须遵守的实现边界

1. YOLO 只识别三类整块组件：正常、需要清洗、需要维修。
2. 区域和组件位置来自任务、备注和人工确认，不来自视觉猜测。
3. RGB 黑化只能表述为“疑似热斑，建议红外复检”。
4. 所有智能体动作先生成草稿，必须人工确认后执行。
5. 本地规则优先，非预设问答才调用云端 API。
6. PostgreSQL 是业务事实来源；Redis 只保存队列和临时状态。
7. YOLO Worker 必须原生运行在 macOS，以使用 MPS；Django、PostgreSQL、Redis 可运行于 Docker。
8. 先完成可演示的端到端闭环，再扩展训练平台细节。

## 推荐第一批开发任务

1. 建立 `frontend`、`backend`、`ai_worker`、`data`、`scripts` 目录。
2. 建立 Docker Compose：Django、PostgreSQL、Redis。
3. 建立 Django 模型和演示电站初始化命令，生成 4 区、12 阵列、240 组件和 30 天历史数据。
4. 把当前静态原型拆成 Vue 布局、路由和组件。
5. 完成登录、注册、审核状态接口。
6. 先用可控模拟 Worker 跑通“上传—进度—结果—报告”，再接入真实 YOLO。

## 第一阶段完成定义

在一台新启动的演示 Mac 上执行一键启动后，控制人员可以登录、上传一组演示素材、看到进度、得到三类识别结果、在地图中看到状态更新，并导出一份报告。即使尚未训练最终模型，也必须使用明确标记的模拟适配层跑通完整链路，且后续替换真实 YOLO 时不修改业务接口。
